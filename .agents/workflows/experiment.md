# One bounded research experiment

1. Read the current state, authority, SPEC, ML plan and evaluation contract. Pick one falsifiable hypothesis and baseline. Inspect existing runs and git changes.
2. Write a protocol before executing: experiment ID, policy/use case, exact source/data/split identities, licence/approval evidence, candidate/seed roster, mutable candidate paths, frozen evaluator paths, metric/count/uncertainty gates, host and time/cost/memory limits, kill conditions.
3. Compare the exact source and resource envelope with current AUTHORITY. Use existing approval without asking again. Review licences/provenance before asset access; exclude ambiguous or gated sources. Seek input only for scope outside that authority, not ordinary implementation or already delegated source selection.
4. Validate admission, then run the smallest fixture. Run the bounded candidate only if the fixture passes. Keep complete and failed directories immutable. Never tune on test or mutate the evaluator to raise a score.
5. Save exact commands, actual environment and source hashes. Enroll the manifest hash outside the output, replay, and repeat a confirmatory result from a fresh directory. Compare substantive artifacts; explain environment differences.
6. Record results, uncertainty, negative results and next falsifiable action in LEDGER and STATE. Separate measured values, literature reports, inference and proposal. A fixture is not evidence for a real safety claim. No uploads, messages, public release or background campaign follow automatically.
