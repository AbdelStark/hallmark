# 0001: hybrid target, exact software foundation first

Date: 2026-10-20. Owner: Abdel. Status: accepted for initialization.

The user requested a private Hallmark repository, agent-native initialization, detailed technical specifications and research. This authorizes creating and populating the private repository, not a public launch or ongoing compute campaign.

Preserve the existing hybrid design: hardware provenance for model execution, ZK for classifier execution, common transcript binding. Build the smallest useful offline research foundation now: real fitting of a weak synthetic-data baseline, exact integer execution, frozen calibration/evaluation and auditable artifacts. Do not create mock proof/TEE adapters that can be mistaken for genuine mechanisms.

Use a byte-linear baseline to expose arithmetic/coverage/threshold contracts without selecting a real policy, checkpoint or prover prematurely. This is an engineering floor, not the proposed production classifier. Keep training optional and core verification free of ML runtime dependencies.

Consequences: a useful runnable project exists, but no safety-quality result, cryptographic proof, TEE attestation, deployment, partner engagement, publication approval or release licence is implied. Real-data/model/prover work starts with explicit admission and a bounded budget. Protocol/evaluator changes require a new decision and revalidation.
